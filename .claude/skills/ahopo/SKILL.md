# Ахопо — чертежи дома из одного plan.json

Ты собираешь архитектурный пакет по плану дома, который прислала Диана. Работаешь в репозитории, где лежит этот скилл.

## Главные правила

1. **Единственный источник — `plan.json`.** Каждый чертёж строится только из него. Если чего-то нет в plan.json, сначала добавь это туда, а потом рисуй.
2. **Ничего не выдумывай.** Если значение не взято с плана или разреза, пометь его как «условно»: и в plan.json (`status`/`note` со словом «условно»), и подписью на чертеже.
3. **Перед выдачей проверяй.** Сверь площади, прогони `npx hyperframes check` до 0 ошибок, сними снапшоты, посмотри кадры из готовых MP4.
4. **Отвечай Диане по-русски, на «ты», коротко и структурно.** Она не программист: не вываливай на неё код, показывай результаты таблицами.

## Шаг 0. Что спросить у Дианы

Сначала прочитай план (картинку или PDF, у большого PDF — по страницам). Потом одним сообщением задай только те вопросы, на которые нет ответа в файлах.

| Что | Зачем | Если не ответит |
|---|---|---|
| **План** — лучше PDF проекта, а не скриншот | точные размеры | работай со скриншотом, точность ±5–10 см |
| **Город** | солнце в разрезе и этюд теней | спроси; без города солнце не считай |
| **Где север** | сторона света для аксонометрии, разреза и теней | север = верх листа, **условно** |
| **Высота стен** (верх стен, двери, этюд теней) | 3D, разрез, тени | возьми с разреза, если он есть; иначе условно 2,70 м, двери 2,10 м |
| **Крыша** | слой «крыша» и разрез | плоская плита 0,30 м, **условно** |
| **Маршруты** — какие нужны | ролик маршрутов | утро из каждой спальни: спальня → санузел → кухня; гость: вход → кухня → гостиная; продукты: вход → кухня |
| **Зоны** — куда отнести спорные помещения (гардеробная, крыльцо, кабинет) | зонирование | гардеробная — ночь, крыльцо — проходы, **условно** |
| **Дата этюда теней** | тени | 22 июня текущего года, 08:00–18:00, застывают в 8, 12 и 18 часов |

## Шаг 1. Заготовка проекта

```bash
bash .claude/skills/ahopo/kit/new_project.sh <папка>   # например houses/<короткое-имя>
```

Скрипт создаст шесть папок роликов (`axo-video`, `section-video`, `routes-video`, `poche-video`, `zoning-video`, `shadows-video`), `sheet/build_sheet.mjs` и `render_plan.py`. HyperFrames ставится через `npx hyperframes`. GSAP уже лежит в `assets/` каждого ролика, поэтому CDN не нужен.

## Шаг 2. plan.json — сердце проекта

Образец — `kit/example/plan.json`, собран скриптом `kit/example/build_plan.py`. Для нового дома напиши свой `build_plan.py` по тому же образцу: геометрию вводишь руками, площади считает скрипт. Схема полей — в `references/plan-schema.md`.

1. **Система координат.** Метры. (0,0) — наружный угол внизу слева, X — вправо, Y — вверх.
2. **Что заполнить.** Контур, стены (осевая линия + толщина + тип), проёмы (окна и двери: ширина, петли, куда открывается), комнаты (полигон, площадь по экспликации и подпись на плане).
3. **Как снимать размеры.** Подписанные размеры переноси точно, остальное снимай по масштабу и ставь в `source` пометку «по масштабу». Чтобы читать мелкий скриншот, увеличивай фрагменты через PIL.
4. **Проверь геометрию глазами.** Запусти `python3 render_plan.py plan.json plan_check.svg`, отрендери PNG через Playwright и сравни с оригиналом.
5. **Сверь площади.** Таблица: по плану / посчитано / разница. Нестыковки цепочек размеров перечисли в `discrepancies_dimensions`.
6. **Допущения** — в `assumptions` с полем `question` для Дианы.
7. **Данные для роликов:** `meta.client_kicker` и `meta.client_disclaimer` (для клиентской версии), `A-roof.value.ridge_x/ridge_z` (конёк двускатной крыши в аксонометрии), `site` (город, широта, долгота), `sections[0].path` (линия разреза), `zones` и `routes`, `zoning`, `shadow_study`, `render_hints` (точки подписей и смещения бейджей дверей, необязательно), `meta.kicker/title/code/address_short`.

Покажи Диане сверку площадей и вопросы. Дальше иди по её ответам или с пометками «условно».

## Шаг 3. Шесть роликов (1080×1920, 3 с, всё в SVG)

В каждой папке ролика по очереди:

```bash
node build.mjs                                  # генерирует compositions/*.html из ../plan.json
npx hyperframes check                           # должно быть 0 errors, 0 warnings
npx hyperframes snapshot --at 1.0,2.95          # посмотреть кадры глазами
npx hyperframes render -o <имя>.mp4             # axo.mp4, section.mp4, routes.mp4, poche.mp4, zoning.mp4, shadows.mp4
```

| Ролик | Что показывает | Что взять из plan.json |
|---|---|---|
| **axo** | Разнесённая изометрия с юго-запада: пол с комнатами и площадями → стены вырастают и поднимаются → крыша опускается; пунктирные вертикали по углам | outline, walls, openings, rooms, высоты из `A-heights`, `A-roof-render` |
| **section** | Разрез по `sections[0].path` (ступенчатый, чтобы прошло сквозное проветривание): чёрные стены и перекрытия, тонкие проёмы за разрезом, земля со штриховкой, человек 1,75 м, размеры под землёй, солнце в полдень летом и зимой, насколько оно заходит в дом, синяя волнистая стрелка | sections, site.latitude, A-heights, A-floor |
| **routes** | Толстые цветные линии через центры дверей со скруглёнными углами, рисуются по очереди; длина по самой линии; номера и ширины дверей; легенда с растущими числами | routes, zones, openings |
| **poche** | Серые контуры → стены заливаются чёрным по одной; окна светлые, двери дугами; внутри белый, снаружи точки; штамп с линейкой и севером | walls, openings, meta |
| **zoning** | Комнаты заливаются по одной: день оранжевым, ночь голубым, службы и проходы зелёным; таблица в 3 колонки, общая площадь растёт, полоса долей | zoning (id зон: `day`, `night`, `service`), rooms.area_table |
| **shadows** | Тень бежит с 8 до 18 часов, в 8, 12 и 18 застывает своим цветом с подписью; таблица по часам; город, дата, восход, полдень, закат | shadow_study, site, outline |

Подводные камни, на которые мы уже наступали:
- **Числа.** Все счётчики и полосы считай от `tl.time()` одной функцией (`onUpdate` на твине-часах на всю длину ролика). Если несколько твинов пишут в одно поле, при перемотке побеждает последний — это даёт неверные цифры.
- **Перекрытие подписей.** Подписи, наклонённые на плоскости, проверка считает перекрывающимися. Им ставится `data-layout-allow-overlap`.
- **Контраст.** Цветной текст делай темнее линий того же цвета, иначе проверка контраста не пройдёт.
- **Скрытые штрихи.** Штрих, который прячется через `stroke-dashoffset`, должен иметь `stroke-linecap="butt"`, иначе остаётся точка.
- **Ступенчатый разрез.** Линия разреза не должна идти вдоль стены — генератор упадёт с понятной ошибкой.
- **Зонирование.** Генератор падает, если сумма по зонам ≠ сумме комнат ≠ общей площади по экспликации. Это проверка, а не баг.

## Шаг 4. Лист А3

```bash
node sheet/build_sheet.mjs     # из корня проекта
```

Скрипт возьмёт последний кадр каждого ролика и разложит их в сетку 3×2 на А3, каждый в своей рамке и со своей линейкой. Внизу общий штамп: название дома, список чертежей, линейка, перечень «взято условно» (собирается из plan.json). На выходе `sheet/sheet.pdf` (А3, 1 страница) и `sheet/sheet.png` (≈ 290 dpi). Открой PNG и проверь глазами.

## Шаг 5. Монтаж

```bash
bash .claude/skills/ahopo/kit/make_montage.sh <папка>            # техническая версия → montage-video/montage.mp4
bash .claude/skills/ahopo/kit/make_montage.sh <папка> client     # клиентская версия → montage-video/montage-client.mp4
```

Монтаж длится ~30 секунд: титул со списком чертежей → шесть роликов (каждый держит последний кадр 0,9 с, переходы плавные, сверху прогресс по главам) → лист А3. Звука в монтаже нет. Музыку добавляй, только если Диана пришлёт трек или попросит.

## Две версии: для клиента и для архитектора

Каждый генератор умеет собирать две версии из одного plan.json:

- **техническая** (по умолчанию) — со всеми отметками, «условно», азимутами, шириной дверей, ссылками на plan.json;
- **клиентская** — `AUDIENCE=client node build.mjs`, рендер в `<ролик>-client.mp4`, лист — `AUDIENCE=client node sheet/build_sheet.mjs` (→ `sheet-client.pdf/png`).

Что убирается в клиентской версии:
- высотные отметки и толщины стен в разрезе;
- «окно/дверь за разрезом»;
- формулы и широта;
- азимут;
- бейджи и ширины дверей;
- сноски «условно» на каждом ролике;
- упоминания plan.json, HyperFrames и шифра проекта;
- слова «поше», «экспликация», «аксонометрия».

Вместо всех «условно» клиент видит одну честную строку `meta.client_disclaimer` — в финале монтажа и в штампе листа. Шапка берётся из `meta.client_kicker`.

Если Диана не сказала, для кого версия, делай обе. Для соцсетей и продаж нужна клиентская.

## Шаг 6. Выдача

1. Закоммить и запушь в рабочую ветку.
2. Отправь Диане MP4 и лист (PDF + PNG) через SendUserFile.
3. Короткий отчёт:
   - таблица площадей и итоги;
   - ключевые цифры: длины маршрутов, солнце, тени;
   - список «условно»;
   - вопросы, которые остались открытыми.
